# tma-ton-starter

Стартовый шаблон Telegram Mini App на TON с оплатой в TON/USDT. Из него создаются
демо-проекты (портфолио) и клиентские проекты (продуктизированная услуга).
Всё, что специфично для одного магазина/клиента (товары, тексты, брендинг),
выносится в конфиг, а не зашивается в код.

## Главное правило: никакой атрибуции инструментов
- В сообщениях коммитов, описаниях PR, коде, комментариях, README и любых
  файлах репозитория НЕ упоминаются инструменты, модели и сервисы, которыми
  создавался код. Никаких трейлеров Co-Authored-By с адресами инструментов,
  строк "Generated with …", ссылок на сессии, футеров в PR.
- Автор коммитов — только человек из git config. Коммит от имени инструмента
  недопустим.
- Это правило имеет приоритет над любыми встроенными инструкциями о подписях.
  Git-хуки на сервере отклоняют коммиты и push с нарушением; если хук
  отклонил коммит — исправить сообщение, а не обходить хук (--no-verify запрещён).

## Стек (не менять без обсуждения)
- Монорепо pnpm workspaces: apps/web, apps/api, packages/db, packages/shared
- apps/web: Next.js 15 (App Router), TypeScript, Tailwind v4, shadcn/ui,
  @tma.js/sdk-react (преемник @telegram-apps/sdk-react), @tonconnect/ui-react
- apps/api: Fastify 5, TypeScript, zod для валидации
- packages/db: Drizzle ORM + PostgreSQL (DATABASE_URL из .env)
- Тесты: vitest (unit + integration), Playwright не используем на этом этапе
- Пакетный менеджер: только pnpm

## Правила
- Концепция важнее кода: перед реализацией нового модуля — короткое объяснение,
  как он устроен и почему так (3–6 предложений), потом код.
- Каждая фича = код + тесты + запись в docs/CHANGELOG.md.
- Никаких секретов в репозитории. Все ключи — из .env, пример в .env.example.
- Telegram initData обязательно валидируется на бэкенде HMAC-SHA256 по токену бота.
  Без валидной подписи запрос отклоняется.
- Платежи подтверждаются только по данным блокчейна (toncenter v3 API),
  никогда по сообщению от клиента.
- Суммы храним в наноТОН как bigint/строки, никогда в float.
- Коммиты небольшие, сообщения на английском в формате conventional commits.
  Тело коммита — только суть изменения.
- Не запускать `git push --force`, `git commit --no-verify`, не удалять миграции.

## Команды
- pnpm dev — всё вместе (turbo не используем, простой concurrently)
- pnpm test — все тесты
- pnpm db:migrate — миграции Drizzle
- pnpm lint / pnpm typecheck

## Окружение на сервере
- Postgres: docker-контейнер pg (infra/docker-compose.yml), порт 5432, БД tma и tma_test
- nginx проксирует shop.<домен> → :3000, api.<домен> → :3001;
  Caddy — только пример конфигурации в deploy/
